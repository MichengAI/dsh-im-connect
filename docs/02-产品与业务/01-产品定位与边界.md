# 产品定位与边界

更新时间：2026-08-18 00:10（Asia/Shanghai）

## 一句话

`dsh-im-connect` 是 DeepSeek Harness 的 IM 助理：用户在微信、企业微信、钉钉、飞书、QQ、Telegram 里驱动本机 DSH agent。会话与 Web 分列，工具批准可以在聊天里完成。

操作步骤见 [使用说明](./04-使用说明.md)。

工作区交互对标千问办公：左侧「任务 / 频道」分列，IM 会话独立，不和网页任务混在一起。

它是 cc-connect 的 DSH 对位产品，不是 dsh-im 的渠道合集，也不是 dsh-im-gateway 的 24 渠道覆盖版。

## 目标用户

- 已经在本机使用 `dsh web` 的开发者
- 希望用国内常用 IM 远程看会话、下任务、批准工具
- 需要回复出现在 DSH Web 同一套会话里

## 要解决的问题

1. 人不在电脑前时，仍能继续本机 agent 工作
2. 工具批准不必回到 Web 页面点击
3. 多个 IM 共用同一套会话、命令和安全策略
4. 新增渠道只改适配器，不改引擎

## 已拍板的产品决定

| 项 | 决定 |
|---|---|
| 已接渠道 | 微信、企业微信、钉钉、飞书（含 Lark 卡）、QQ、Telegram |
| 设置入口名称 | **IM助理** |
| 设置页视觉 | 1:1 还原「IM 频道」列表稿，见 [设置页交互](./02-设置页交互.md) |
| 参考项目 | 只对照源码，不安装、不替换 dsh-im / dsh-im-gateway |
| 模型与工具包 | 跟随当前 DSH profile；缺省再用 `standard` preset |
| 任务与频道 | 网页任务和 IM 会话分开，工作区两个页签 |

## 明确不做

| 不做 | 原因 |
|---|---|
| 接入 Claude Code / Codex / Cursor 等外部 CLI | 那是 cc-connect 的 Agent 层；本项目 Agent 固定为 DSH |
| 做成独立守护进程 | 必须作为 DSH bundle 插件 |
| 一次上 20+ 渠道或骨架渠道 | 只做上面这些可用渠道 |
| 各渠道自己创建 HTTP 会话 | 会让 Web 与 IM 会话分裂 |
| 逆向个人微信协议 | 微信只走腾讯官方 iLink |
| 在引擎里写死平台名 | 用能力接口扩展 |
| 设置页出现「千问办公」 | 文案改成「本机助手」 |

## 与参考项目的产品差异

| 维度 | dsh-im | dsh-im-gateway | cc-connect | 本项目 |
|---|---|---|---|---|
| 运行时 | DSH 插件 | DSH 插件 | 独立 Go 进程 | DSH 插件 |
| Agent | 本机 HTTP 会话 | 进程内 agent | 本机 CLI | 进程内 DSH agent |
| 产品入口 | IM机器人 | IM 网关 | 独立 Web | **IM助理** |
| 会话是否进 Web | 否 | 是 | 否 | 是 |
| 已接渠道 | 7 个做深 | 24+ | 13+ | 微信 / 企微 / 钉钉 / 飞书 / QQ / Telegram |

## 成功标准

1. 安装后在设置里看到 **IM助理**
2. 设置页长得像视觉稿：未连接显示「配置」，已连接显示「已连接」+ 开关
3. 七个渠道至少能各连上并完成文字往返
4. 工作区「频道」里能看到对应 IM 会话，且「任务」里没有它
5. 需要批准时，聊天里回「批准 / 拒绝」即可

## 非目标指标

- 不追求渠道数量超过 dsh-im-gateway
- 不追求复刻 cc-connect 的 cron、TTS、多 Agent
- 第一期不承诺媒体完整收发
