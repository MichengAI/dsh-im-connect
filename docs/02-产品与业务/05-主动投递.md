# 主动投递

更新时间：2026-09-06 21:21（Asia/Shanghai）

## 配置账号与接收目标

1. 在「设置 → IM助理」选择一个已接入账号。
2. 为账号设置明确名称，例如「工作助理」。复用现有名称，不另设投递别名。
3. 开启「允许主动投递」。新旧账号默认关闭，同一渠道内允许投递的账号名称不能重复。
4. 在「接收目标」新增目标。优先从已知会话中选择，填写目标名称；未出现的目标可使用「手动填写（高级）」输入平台原生 ID。
5. 保存后可点击目标行的「测试投递」图标。测试会真实发送一条固定文字，只有用户点击才发送。

已知会话来自当前账号的持久化会话映射，不是平台通讯录，也不把聊天标题当作群名。没有候选时，可在接收开启后与机器人建立会话，再刷新。目标可以在 Chat 中使用 `im_target_save` 保存。

目标 ID 自动生成。目标名称和路由可编辑，ID 不变；删除再新建会得到新 ID。删除目标会使旧 ID 的定时投递失败。移除账号会删除该账号配置内的目标。

## Chat 与任务

插件随包注册 `im-send` Skill，无需复制到全局技能目录：

> /im-send 用飞书「工作助理」，把刚才的总结发到「产品研发群」。

也可直接用自然语言要求发送。模型通过工具动态查询账号与目标，用稳定的 `accountId + targetId` 发送。信息明确时不重复确认；名称不唯一或缺少收件目标时补充选择，不自动换账号。

定时任务创建时应记录明确的账号 ID、目标 ID 和独立运行能理解的说明。每次发送会重新检查投递许可；改名不会影响 ID，关闭许可后下一次发送会被拒绝。

本期工具仅供本机主 Chat 与独立任务。外部 IM 会话及子 Agent 不获得整个 Host 的投递账号权限。工具权限仍经过 Host 工具执行管线；调度方是否允许调用由其自身策略决定。

## 开关与连接

「接收消息」与「允许主动投递」独立：前者控制新消息是否驱动 Agent，后者控制是否允许主动发送。只投递时保留发送所需连接；部分平台仍需保持底层接收以维持连接或更新上下文，但不会触发 Agent。两个开关都关闭时停止连接。

允许投递不表示当前在线或平台一定接受。离线调用明确失败，不默认排队补发；连接恢复后由调用方重新发起。

## 平台目标

| 平台 | 原生目标 | 限制 |
|---|---|---|
| 飞书、Lark | 群 Chat ID；私聊 Chat ID 或 Open ID | 需要应用可见范围、机器人发送权限 |
| Telegram | 数字 Chat ID，群可附加正整数话题 ID | 用户先联系机器人或机器人已加入群 |
| 企业微信 | 私聊用户 ID 或群 Chat ID | 使用智能机器人主动消息接口，需保持连接 |
| 钉钉 | 私聊 Staff ID 或群 Open Conversation ID | 使用应用机器人主动 API，不依赖临时 Webhook |
| QQ | 用户 OpenID 或群 OpenID | 受主动消息许可和平台频率限制 |
| 微信 | iLink 用户 ID | 仅私聊，需要已保存上下文，仍可能被平台限制；不承诺固定额度或窗口 |

## 结果与恢复

- `sent`：平台接受全部分片，不表示已读。
- `failed`：已确认未发送，按返回原因处理。
- `partial`：部分分片已被接受，检查 `sentParts`、`totalParts` 与 `uncertain`。
- `unknown` 或 `uncertain=true`：网络或回执异常导致无法确认，先检查接收端，不自动重发整条。

只支持非空文字，每次最多 256 KiB；按平台长度及保守字节预算分片，拼接后保持原文。无默认重试、离线积压或已读跟踪。

关闭投递开关可阻止后续发送；已经被平台接受的消息不能通过开关撤回。升级前可备份状态目录中的 `channels.json`，恢复配置前停止插件并保留当前副本；凭据仍由原有凭据存储管理。
