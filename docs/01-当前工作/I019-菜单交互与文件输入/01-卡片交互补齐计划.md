# 卡片交互补齐

状态：进行中

更新时间：2026-09-11 07:28（Asia/Shanghai）

目标：命令、卡片和文字回复使用相同的执行入口，用户能直接选择、看到处理反馈，并知道下一步去哪里。

按依赖顺序实施，每项独立提交：

1. 原卡片收口：有效选择后移除按钮，显示已选择；执行结果仍由后续回复准确说明。更新失败不重发、不重试操作。
2. 列表直接选择：支持按钮的渠道发送 `/sessions`、`/workspaces`、`/models` 即进入分页选择，文字渠道保留完整命令。
3. 状态操作：根据已读取的运行、目标和队列状态提供有效操作；未知状态只提供查询入口。
4. 降级诊断：区分容量、能力和发送失败，保留脱敏日志；已发送卡片更新失败不得另发副本。
5. 钉钉操作卡片：核对模板和 Stream 回调契约，不能以链接按钮或普通 AI 卡片冒充可执行命令按钮。

所有项目保持准入、命令权限、操作者、会话绑定和一次消费校验。原生展示、回调权限和手机排版需要真实账号验收，不以模拟 API 测试替代。

## 已完成

- 钉钉操作卡片：使用官方公共请求按钮模板，注册 TOPIC_CARD 并及时确认回调。聊天目标来自已发送卡片记录，检查原操作者、卡片 ID、动作白名单和有效期；继续进入引擎权限和一次消费检查。完成选择后只更新原实例并清空按钮。创建失败可降级，投递结果未知不补发。钉钉及选择测试 32 项全通过；完整测试 630 项：607 通过、0 失败、23 跳过。关联提交：本次 `feat: support DingTalk command cards and stream callbacks`。尚未本机安装、未推送、未发布，真实渠道显示与应用权限待维护者验证。

## 钉钉契约依据

- 请求型按钮的 `id`、`request: true`、`sys_full_json_obj.msgButtons` 和公共模板 ID，来自[官方 Python SDK 的 CarouselCardInstance](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/8d8bb1c630848fee1ae8c7bdd11bc1b78097b611/dingtalk_stream/card_instance.py)。只使用其文字及按钮区域，不生成图片轮播。
- `content.cardPrivateData.actionIds`、`outTrackId`、`userId`、`userIdType` 来自[官方 Go SDK 回调模型](https://github.com/open-dingtalk/dingtalk-stream-sdk-go/blob/d8d6e1f19d68b231c1514fdac973d866a2882b93/card/model.go)。请求内容中的 `content` 是 JSON 字符串。
- `/v1.0/card/instances/callback` 与 `socketCallBackResponse` 来自本仓库安装的官方 Node SDK 2.1.4；卡片创建、投递和更新沿用现有官方 REST 接口。
- 自动化使用真实字段构造和模拟平台响应，不等于已验证账号对公共模板的权限、模板当前发布状态或手机排版。平台拒绝时保留文字降级。
