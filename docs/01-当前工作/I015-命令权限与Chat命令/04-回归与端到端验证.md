## ISSUE-1：P1 新建会话失败

复现步骤：

1. 在隔离宿主添加可用的本地模拟模型和 Telegram 账号，工作区选择已创建的 workspace-one，启用接收消息。
2. 从模拟 Telegram 投递文字，先在设置页批准待准入的测试用户，再投递一条文字。
3. 收到“消息处理失败，请查看本机日志。”；模型服务未收到请求，频道列表没有新会话，见 [失败后的频道](05-端到端验证证据/channel-after-failure.png)。
4. 投递 `/new`，收到相同注入错误。另在网页正常创建一个会话，用 `/session 1` 接续成功后再投递 `/new` 和 `/workspace 1`，仍失败。

真实日志：

```text
[router] telegram_130ebed2f48d 使用模型 e2e-local/e2e-model
[telegram_130ebed2f48d] 合并投递失败: cannot get property "agent" without inject
```

命令回执：

```text
命令执行失败：cannot get property "agent" without inject

查看用法：/help；确认当前会话：/status
```

证据：[网关日志](05-端到端验证证据/gateway.txt)、[完整模拟回执及模型调用计数](05-端到端验证证据/test-transcript.json)。网页对照成功和接续后正常回复排除了“模拟模型无法工作”的解释。已定位到真实新建生命周期的 Agent 注入约束；本轮未进行生产代码修复，也不将具体出错源码行或版本引入点当成已确认结论。

修复验收需要保留真实宿主创建路径的回归，至少验证首条消息、`/new`、工作区切换成功，以及失败不丢原绑定。

## ISSUE-2：P2 窄屏弹窗被聊天区域遮挡

复现步骤：

1. 在已有会话页面打开设置 → IM Assistant → Telegram 账号设置，1280×720 下弹窗可用，见 [桌面弹窗](05-端到端验证证据/settings-english.png)。

3. 恢复 1280×720，再改为 390×844，问题再次出现，见 [重复复现](05-端到端验证证据/settings-narrow-repeat.png)。

本轮只确认组合界面的可见故障，未断言一定由插件或宿主某个具体层级样式造成。修复后需验证打开、关闭、滚动和视口变化。
