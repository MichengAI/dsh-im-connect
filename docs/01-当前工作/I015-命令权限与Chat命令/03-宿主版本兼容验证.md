## 旧版断点

旧版真实 `HostConnectionService` 使用 RPC channel 的 trusted-host 注册机制，没有 `requestRejection` 和 `authenticatedUrl`。将已有管理认证测试指向这两版，各出现 11 项失败、1 项通过、1 项跳过；其中多项失败发生在测试登录准备阶段，不能当成 11 个独立产品缺陷。

另行使用真实旧版 Connection 原型走插件管理 handler，确认 `/api/dsh-im-connect/channels` 返回 503。此结果与 `manager.ts` 缺少认证服务时关闭管理入口的逻辑一致，不能通过取消校验来实现兼容。

旧版 npm 未发布同版本 `dsh-api-session-controller`，而本插件的模型、历史、队列、会话接续等调用当前 `sessionController` 公共服务。回兼需要独立的旧版会话控制适配，以及保留等价认证边界的管理入口；单改 peer 范围无法完成。

## 最新版差异

首轮 0.1.5-rc.1 结果为 492 项通过、3 项失败，均来自契约夹具跟不上宿主内部依赖：

1. `SessionCommandController.prompt()` 新增 `agent.inbox.nextTurn/nextStep` 与 `session.snapshotEvents()` 去重检查，旧夹具没有这些字段。
2. 图片准入从 `dsh-attachment` 导出的自由函数迁移至 `AttachmentStore.admitPromptContent()`，旧夹具只提供 `saveImages()`。
3. prompt 路径新增 `fileUploads.bindPrompt()`，即使只含图片也执行回执绑定。

测试公共夹具补齐空输入队列，并按实际宿主导出选择真实附件准入函数或方法，继续覆盖图片持久化重开、拒绝不支持图片的模型、串行切模。文件服务夹具断言回执列表为空；文件上传本身仍不在这些测试的覆盖范围。

插件始终调用 `sessionController.prompt()`，没有直接依赖这些变化的内部接口，所以无需在生产代码中增加版本分支。源码核对了会话控制所用 12 个方法、Agent 创建与恢复选项、标题的 `user/provider/fallback` 来源；未发现新的调用断点。

## 工程调整与验证

- 所有 DSH peer 依赖使用精确并集 `0.1.2-rc.1 || 0.1.5-rc.1`；开发依赖为 `0.1.5-rc.1`，不锁到旧版。
- 同步 lockfile；非 DSH 包没有版本升级。npm 在已有旧版 peer 树上直接更新发生 ERESOLVE，因此在隔离目录重新解析 DSH 节点，保留其他锁定版本；未使用 `--force` 或 `--legacy-peer-deps`。
- 全新隔离目录 `npm ci --ignore-scripts` 成功；工作区最新版依赖构建成功。
- CI 改为两个支持版本的矩阵，复用全部测试，保留全部契约检查；当前只完成本地矩阵验证，远程 CI 等提交后运行。
- 隔离安装曾遇镜像源解析缓慢，改用官方 npm registry 后完成；两个旧版缺包结论以实际 npm 发布记录和源码为准。

复现单个支持版本（在仓库根目录 PowerShell 执行，使用独立临时目录，不操作用户 Profile）：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
$dshVersion = '0.1.5-rc.1' # 或 0.1.2-rc.1
$contractDir = Join-Path $env:TEMP "dsh-im-contract-$dshVersion"
npm install --prefix $contractDir --registry=https://registry.npmjs.org --no-audit --no-fund "@deepseek-ai/dsh-api-session-controller@$dshVersion" "@deepseek-ai/dsh-commands@$dshVersion" "@deepseek-ai/dsh-attachment-local@$dshVersion" "@deepseek-ai/dsh-client-connection@$dshVersion"
if ($LASTEXITCODE -ne 0) { throw '契约依赖安装失败' }
$contractPackages = Join-Path $contractDir 'node_modules\@deepseek-ai'
$env:DSH_CHAT_CONTRACT_ROOT = Join-Path $contractPackages 'dsh-api-session-controller'
$env:DSH_ATTACHMENT_CONTRACT_ROOT = Join-Path $contractPackages 'dsh-attachment-local'
$env:DSH_CONNECTION_CONTRACT_ROOT = Join-Path $contractPackages 'dsh-client-connection'
npm test
```
