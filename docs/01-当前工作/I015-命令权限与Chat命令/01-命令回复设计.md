# 命令回复设计：常用操作

状态：已实施基础回复与关联指引，真实渠道显示待验证
更新时间：2026-09-10 15:20（Asia/Shanghai）
范围：按当前代码梳理文字交互，不是实际手机界面验收。例子中的名称、数量和模型均为演示；实际回复必须使用已读取的数据。
关联：[迭代总览](00-迭代总览.md) · [宿主扩展命令与异常回复](02-宿主扩展命令与异常回复.md)

实施边界：完整扩展结果示例属于条件模板，当前实际展示原文加相关操作，不代表已翻译全部宿主状态。已落地内置命令的结果、列表、用法、关联动作和空状态；宿主扩展保留原始正文，按命令附加指引。下文依赖额外结构化信息的完整结果模板是条件设计，不通过解析自然语言伪造字段。状态使用宿主投影；读取失败省略可选字段或标记不可读取。手机消息分段沿用渠道现有机制，超长条目仍可能分段。

语言：插件文案支持中文和英文，读取宿主 `settings.get("locale").preference`，与网页保存的语言选择一致。`en` 及其地区变体使用英文；无明确偏好、其他语言或读取失败时兼容中文默认。IM 无浏览器自动语言，用户可在网页明确选择语言。动态名称、路径、ID、消息正文和宿主结果不翻译。

## 1. 用户体验约定

用户不应为了完成一个操作反复查询帮助。每次回复回答三件事：现在是什么结果、作用于哪里、接下来怎么做。

- 查询：当前状态 → 可选项或用法 → 两三个相关操作。
- 修改成功：确认结果 → 关键变化或影响 → 一两个相关操作。
- 列表：列表范围与当前项 → 编号条目 → 选择示例、翻页方式。序号按当前用户查询结果使用，15 分钟有效。
- 失败：没有完成什么 → 可理解的原因 → 原状态是否保留或是否部分成功 → 能直接复制的恢复操作。
- 提交和执行分开：“已提交”“已请求停止”不能写成“执行完成”“已停止”。
- 成功不附通用警告。影响默认模型、保留队列等真正影响用户判断的事实，放在对应操作回复中。
- 手机端默认纯文本、短段落，操作示例独占一行。不能依赖 Markdown 表格、颜色、按钮或下拉菜单。
- 普通成功回复以 3–6 行为目标；列表按现有渠道消息限制拆分，标题与条目、条目与操作不被切散。历史正文不硬截成几个字符。
- 用名称优先于长 ID。会话列表仍保留完整 ID 作为可复制的接续方式；新建成功不必展示 ID，/status 可查看，分叉部分成功必须给完整 ID。
- 只展示实际可执行的关联命令。未注册的扩展命令不推荐；无当前会话时引导创建；无可选推理等级时不推荐切换等级。
- 元数据读取失败不能把已完成操作改报失败；显示已确认的结果，其余标记“暂时无法读取”，不猜模型、权限或状态。
- 同一命令的别名共用回复。中文机器人优先中文；英文名、模型标识、路径保持原值。

## 2. /help：找到入口

用途：用户第一次连接或不知道下一步怎么做时，提供任务导向导航。无需已有会话。

建议回复：

```text
{渠道名称}机器人已连接 DeepSeek Harness。
直接发送文字即可继续聊天；支持的附件类型按当前渠道展示。

会话与工作区
/new  开启新会话，旧会话保留（也可用 /clear）
/sessions  列出会话；/session 2  切换到列表第 2 项
/workspaces  列出工作区；/workspace 2  在第 2 项新建会话
/history  查看当前会话最近的文字记录
/rename 新名称  修改当前会话名称
/fork  从当前会话分叉并切换

模型与推理
/model  查看当前模型；/models  查看可选模型
/reasoning  查看当前推理等级和可选项

任务控制
/status  查看当前会话状态
/stop  请求停止当前运行，保留队列
/steer 补充要求  提交补充指令
/queue  查看排队消息与操作方法

扩展命令（只展示当前会话已注册的命令）
{命令名 + 中文用途，具体见扩展文档}
/export  导出需在网页 Chat 中操作

例如：先发送 /models，再发送 /model 2。
命令单独发送为文字；带图片的说明按普通消息处理。
```

设计说明：不把所有别名、长参数、错误条件塞入首屏；各查询回复负责给出完整操作。尚无会话时说明“直接发消息或 /new 创建后可查看扩展命令”。附件提示只能承诺已确认的渠道能力，不能把接收附件写成支持文件回传。

## 3. /new、/clear：重新开始

当前用法：无参数。沿用当前工作区，使用账号的新会话配置；旧会话保留。/clear 不是清空或删除日志。

```text
已开启新会话
工作区：{目录名称}
模型：{模型名称} · {推理等级，有值才显示}

直接发送消息即可开始，旧会话已保留。
查看或切回旧会话：/sessions
```

已有任务运行：提示“当前任务仍在运行，暂未新建。先发送 /stop，等运行结束后再发 /new”。有待回答问题或审批时优先引导完成该交互，不建议跳过审批。
创建失败：说明仍保留原当前会话，提供 /status；只在确认失败可重试时建议再次 /new。

## 4. /sessions、/sessionlist：找到旧会话

当前用法：/sessions [页码]，每页 10 项，列出宿主可接续的普通会话，并非只列当前工作区。不支持竞品的工作区参数或 --limit。

```text
会话列表 · 第 {页码}/{总页数} 页 · 共 {数量} 个
范围：可接续的普通会话

1. {标题}〔当前〕
   {完整会话ID}
2. {标题}
   {完整会话ID}

切换到第 2 项：/session 2
下一页：/sessions 2
序号 15 分钟内有效；也可用完整会话 ID 切换。
```

只在确有第 2 项或下一页时展示对应示例；后续页继续全局编号，不能重置成 1–10。
空列表：“暂无可接续会话。发送消息或 /new 开始聊天。”越界页：“没有第 N 页；共 M 页。返回：/sessions M”。空列表与越界不能共用“没有更多会话”。
归档项若能可靠识别则标记“已归档，需先在网页恢复”，不给直接可切换的暗示。标题中的换行按单行展示，避免伪装列表结构。

## 5. /session：查看当前绑定或切换

用法：/session；/session <列表序号或完整ID>。

查询：“当前会话：{标题}
工作区：{名称}
会话 ID：{ID}

切换会话：/sessions
查看详细状态：/status”。
成功：“已切换到：{标题}
工作区：{名称}

接下来的消息会发到此会话。
最近记录：/history　重新开始：/new”。不暗示网页点击历史也会改变机器人绑定。
序号过期：“此会话序号已过期，尚未切换。发送 /sessions 获取新列表，再使用 /session 序号。”
目标归档：“该会话已归档，尚未切换。请先在网页恢复，再发送 /session {完整ID}。”
目标被其他聊天绑定：说明不能重复接续、当前会话不变，建议 /sessions 选其他项；不暴露其他聊天身份。

## 6. /workspaces、/workspacelist：选择做事的目录

用法：无参数。/workspace 不带参数也列出工作区。当前不支持 /ws、/wsl。

```text
工作区列表 · 共 {数量} 个
1. {目录名称}〔当前，能确认时才标记〕
   {绝对路径}
2. {目录名称}
   {绝对路径}

在第 2 个工作区开启新会话：/workspace 2
也可发送 /workspace 已列出的绝对路径。
旧会话会保留，账号默认工作区不会修改。
```

工作区 ID 不常驻重复展示，路径承担识别作用；完整 ID 仍可作为输入。
空列表：“还没有可用工作区。请先在网页添加工作区，再发送 /workspaces。”不推荐当前不存在的 /workspace add。

## 7. /workspace：切目录并开始新会话

用法：/workspace <序号、工作区ID或已存在工作区的绝对路径>。当前不是创建任意磁盘目录。
成功：“已在新工作区开启会话
工作区：{名称}
路径：{绝对路径}

旧会话已保留，可以直接发送任务。
查看当前配置：/status　切回旧会话：/sessions”。
无效路径：“没有找到这个已添加的工作区，尚未切换。发送 /workspaces 查看可选项；新目录请先在网页添加。”
运行中或交互待完成：沿用 /new 的前置提示，不把这些情况描述为路径错误。

## 8. /models：挑模型

用法：无参数。保留真实模型顺序和完整标识；能确定当前模型时标记当前项。

```text
可用模型 · 共 {数量} 个
1. {模型名称}〔当前〕
   {provider/model}
2. {模型名称}
   {provider/model}

切换到第 2 项：/model 2
查看当前模型：/model
查看当前模型的推理选项：/reasoning
序号 15 分钟内有效。
```

没有模型：“暂无可用模型。请在网页配置模型服务后，再发送 /models。”不把服务读取失败显示成空列表。

## 9. /model：围绕当前模型就能继续操作

用法：/model；/model <序号或provider/model> [推理等级ID]。

```text
当前模型：{模型名称}
模型 ID：{provider/model}
推理等级：{中文名称或等级ID；未指定则写默认}

选择其他模型：/models
查看推理选项：/reasoning
切换示例：/model {可用的provider/model}
```

有近期有效模型列表才额外显示 /model 2 之类的序号示例；不能让用户复制一个不存在的编号。
成功：“模型已切换为：{名称}
推理等级：{等级}

后续请求使用此选择；与 Chat 一致，也会更新宿主后续新会话的默认选择，其他已有会话不主动修改。
调整推理：/reasoning　查看模型列表：/models”。宿主保存默认值失败时不能声称已经保存成功，需依契约可观测结果区分。
无效模型：说明当前选择未改，给 /models；无效推理等级给 /reasoning。查询不显示成功修改提示。

## 10. /reasoning、/reasonings、/reasoninglist：调整思考深度

当前用法：/reasoning 查看；/reasoning <等级ID> 修改；/reasoning --default 恢复默认。后两个别名只查询，当前不支持数字序号。

```text
模型：{模型名称}
当前推理：{等级}
可选等级：
{ID} — {模型提供的等级名称}
{ID} — {模型提供的等级名称}

切换：/reasoning {一个真实可用ID}
恢复默认：/reasoning --default
更换模型：/models
```

不凭名称承诺具体质量、速度或费用。成功显示新等级及默认选择影响，关联 /model。
不支持可选等级：“当前模型没有可选推理等级。查看当前模型：/model；选择其他模型：/models”。不展示不可执行的等级示例。

## 11. /status、/current：一条消息说明现在在哪、在做什么

当前可直接获取渠道、会话、目录、运行状态和模型选择。Agent、权限、目标和队列属于需要补取可靠数据的设计增强，读取不到时不编造。

```text
当前会话：{标题}
状态：{运行中 / 空闲 / 暂时无法读取}
工作区：{名称或路径}
模型：{名称} · {推理等级}
Agent：{已核实的预设}
权限：{已核实的有效权限，不是账号默认值}
目标：{活跃 / 暂停 / 无目标，可靠读取时展示}
排队消息：{数量，可靠读取时展示}
渠道：{渠道名称} · {渠道连接状态}
会话 ID：{完整ID}

{按状态推荐最多三个动作}
```

运行中：/steer 补充要求、/stop、/queue（有队列时）。空闲：/history、/model、/sessions。目标活跃时优先 /goal pause；未注册目标命令不展示。
没有会话：“当前还没有会话。直接发消息或 /new 开始。”渠道连接正常不能直接写成模型可用、工具正常。

## 12. /stop：让用户知道停了什么

用法：无参数。
已提交：“已请求停止当前运行。
排队消息仍保留。
查看队列：/queue　确认运行状态：/status”。只能确认请求受理时，不能写“任务已停止”。
活跃目标附加：“目标仍处于活跃状态，暂停目标：/goal pause”。目标状态未知用条件提示，已知无目标则不增加该行。
当前空闲且能可靠确认：“当前没有正在执行的任务。{有队列或活跃目标时继续说明}”。停止接口报找不到会话时引导 /status，而不是伪造成功。

## 13. /steer：补要求

用法：/steer <文字>。
成功：“补充要求已提交
{输入内容的短摘要}

查看进度：/status　请求停止：/stop”。不承诺下一条输出已经采纳要求。
无参数：“请在命令后写补充要求。
例如：/steer 只修改登录页面，保留现有配色
查看当前任务：/status”。
长文本回显限定长度，明确省略；不改变实际提交内容。

## 14. /queue：看清还没执行的消息

用法：/queue；/queue remove <消息ID>；/queue steer <消息ID>；/queue edit <消息ID> <新内容>。
查询逐条展示“消息 ID、可理解的队列状态、内容摘要”；ID 保持完整，因为当前操作不支持序号。
列表末尾针对一条真实消息给示例：/queue remove {ID}；/queue edit {ID} 新内容；/queue steer {ID}。将 steer 说明为“调整为补充指令”，不保证立刻执行。
成功分别写：“已移除排队消息：{ID}”“已修改排队消息：{ID}
新内容：{摘要}”“已将排队消息调整为补充指令：{ID}”；关联 /queue、/status。
空列表：“当前没有排队消息。直接发消息继续；查看运行状态：/status”。消息失效：“该消息可能已执行或移除，请发送 /queue 获取最新队列”，不声称改动已完成。

## 15. /history：快速想起聊到了哪里

当前用法：无参数，最多拉取最近 10 条消息范围，再筛选用户与助手文字；不是完整历史，不支持数量参数。
回复标题“当前会话：{标题}
最近文字记录”，正文标明“你：”“助手：”，仅展示实际文字，不能把内部插件提示当成用户发言。
末尾：“继续此会话：直接发消息
换一个会话：/sessions
完整记录：在网页打开当前会话”。
空结果写“最近记录中没有可展示的文字，图片或文件请在网页查看”，不能据此断言整个会话为空。用户发送 /history 5 时应明确数量参数尚未支持，不静默忽略（需要实现参数校验）。

## 16. /rename：识别改的是哪条

用法：/rename <新名称>。
成功：“当前会话已改名为：{新名称}
查看会话列表：/sessions”。有可靠旧名称时可显示“{旧名称} → {新名称}”，不为旧标题额外阻塞成功回复。
空参数：“请填写新名称，例如：/rename 九月出行计划”。失败说明未完成改名，不提供泛化“请查看日志”作为唯一出口。

## 17. /fork：保留原对话，沿新方向继续

用法：无参数；依宿主从已完成回合分叉，不承诺包含未完成的一轮。
成功：“已创建分叉并切换
来源：{原会话标题}
工作区：{名称}

新消息将继续这个分叉，原会话保留。
查看继承记录：/history　切回原会话：/sessions”。
没有完成回合：“当前没有可分叉的完整回合。先完成一次对话后再发 /fork；若只想重新开始，发送 /new。”
部分成功：“分叉已创建，但尚未切换。
当前仍是原会话。
分叉 ID：{完整ID}

稍后接续：/session {ID}”。若工作区挂载失败，明确先到网页处理工作区再接续；不能只给一个暂不可执行的命令。

## 18. 关联动作规则与实施边界

主要路径：/help → /model → /models → /model ID → /reasoning → /status；/sessions → /session ID → /history → 直接聊天；/workspaces → /workspace ID → /status → 直接发任务；/status → /stop 或 /steer 或 /queue；/fork → /history 或 /sessions。

这些是按当前能力制定的回复方案，不修改命令语法。新增状态字段、参数校验、分页计数和中文标签需要代码实现；不应在文案上线时假装已经拥有可靠数据。
当前代码没有 /m、/menu、/ws、/wsl、/preset、/presetlist、/presets、/batch、/send、/cancel、/version 控制命令，不能出现在固定帮助或关联操作里。第三方动态注册同名命令时按真实描述处理，不能认作插件已有内置能力。
