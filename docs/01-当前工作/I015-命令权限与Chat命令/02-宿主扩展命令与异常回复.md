# 命令回复设计：宿主扩展与异常

状态：已实施基础回复与关联指引，真实渠道显示待验证
更新时间：2026-09-10 13:32（Asia/Shanghai）
关联：[常用命令回复设计](01-命令回复设计.md) · [迭代总览](00-迭代总览.md)
依据：当前插件命令分发，以及本机 DSH 已知命令实现。以下扩展仅在宿主已注册时展示。未知扩展不能承诺已逐项覆盖。

实施边界：已落地内置命令的结果、列表、用法、关联动作和空状态；宿主扩展保留原始正文，按命令附加指引。下文依赖额外结构化信息的完整结果模板是条件设计，不通过解析自然语言伪造字段。状态使用宿主投影；读取失败省略可选字段或标记不可读取。手机消息分段沿用渠道现有机制，超长条目仍可能分段。

语言：插件文案支持中文和英文，读取宿主 `settings.get("locale").preference`，与网页保存的语言选择一致。`en` 及其地区变体使用英文；无明确偏好、其他语言或读取失败时兼容中文默认。IM 无浏览器自动语言，用户可在网页明确选择语言。动态名称、路径、ID、消息正文和宿主结果不翻译。

## 1. 动态命令的呈现原则

已知扩展命令提供中文用途和操作指引；真正的执行结果仍以命令提供者为准。不能用“字符串里有 success”判断执行完成，也不能按零散英文子串盲目翻译结果。

如果宿主只返回自然语言、没有可靠的结构化状态：保留原始返回内容，再附简短中文“这个命令做什么、可使用哪些关联命令”。只有能通过结果结构或状态查询可靠判断时，才展示下述完整中文模板。后续实现需按命令维护小型展示适配表，未知命令原样保留输出，不再用通用完成提示掩盖空结果。

关联指引每次最多两三项，随状态改变；不要每条消息末尾都追加 /help。

## 2. /compact：压缩较早上下文

用法：/compact，无参数。执行可能耗时，压缩前置条件和结果由宿主决定。
- 开始且能确认请求已受理：“正在压缩当前会话的较早上下文，完成后会通知你。”只有长耗时才发送一次进度，不为瞬时结果额外刷屏。
- 成功：“较早上下文已压缩
处理记录：{真实数量}
{确有数据时展示估算 token 数量}

可以继续聊天。
查看最近记录：/history　重新开始：/new”。不写“历史已删除”或“节省精确费用”。
- 无需压缩：“当前没有可压缩的较早上下文，可以直接继续聊天。
最近记录：/history”。
- 运行中不可压缩：“当前任务正在运行，暂时不能压缩。
查看状态：/status　请求停止：/stop
任务结束后再发送 /compact”。
- 取消：“压缩已取消。{是否改动历史须以明确结果为准}”。
- 提交或保存异常：准确保留“历史可能已变化”或“压缩已完成但保存失败”，让用户先在网页检查；不能统一替换成“原记录未改变”。

## 3. /goal：长期任务的完整操作入口

用法：/goal；/goal <目标>；/goal edit <新目标>；/goal pause；/goal resume；/goal clear。

无目标查询：
```text
当前没有长期目标。
设置后，助理可围绕目标持续推进。

例如：/goal 审查当前项目，找出并修复登录问题
只执行一次任务：直接发送文字
```

已有目标查询：
```text
当前目标：{目标正文}
状态：{进行中 / 已暂停 / 遇到阻塞 / 已完成}
已开始轮数：{实际轮数}/{上限}
{可靠获取时显示等待调度或未激活状态；阻塞时展示原因}

{按状态展示后续操作}
```

关联矩阵：
| 状态 | 推荐命令 |
| --- | --- |
| 活跃且可继续调度 | /goal pause、/goal edit 新目标、/status |
| 暂停或阻塞 | /goal resume、/goal edit 新目标；阻塞时先说明解除条件 |
| 已完成 | /goal 新目标、/goal clear、/history |
| 活跃但未激活 | /goal resume、/goal edit 新目标，不能只显示“运行中” |

创建成功：“长期目标已设置
目标：{正文}
状态：{真实状态}

查看进度：/goal　暂停目标：/goal pause”。不能宣称模型已经开始执行。
编辑成功：“目标已更新为：{正文}
状态：{实际状态}

查看目标：/goal”。不假定编辑一定唤醒运行。
暂停成功：“目标已暂停，不再按该目标自动发起后续推进。
恢复：/goal resume
当前运行状态：/status”。当前回合是否立即终止需要真实状态核实，不能把暂停目标写成终止全部运行。
恢复成功：“目标已恢复
目标：{正文}

查看进度：/goal　暂停：/goal pause”。
清除成功：“长期目标已清除，会话记录保留。
设置新目标：/goal 新目标
继续普通聊天：直接发送文字”。不承诺当前执行中的回合立即终止。
已有未完成目标时再次创建：“已有{状态}目标：{正文}
修改：/goal edit 新目标
清除：/goal clear”。不要让用户猜为何命令失败。

## 4. /plan：先规划再行动

用法：/plan 开启；/plan <要求> 开启并提交要求；/plan off 退出。注意 /plan 无参数是操作，不是查询。

开启已生效：“计划模式已开启。
直接发送要规划的任务。
退出计划模式：/plan off”。
开启待生效：“已请求进入计划模式，将从后续步骤生效。
退出或取消：/plan off”。保留宿主对 queued、committed、cancelled 的区别。
带要求：“{已开启 / 已请求进入}计划模式
已提交规划要求：{摘要}

查看任务状态：/status　退出：/plan off”。不承诺绝不调用工具等未经宿主约定的行为。
退出已生效：“已退出计划模式，可以继续发送任务。
重新开启：/plan”。退出待生效则明确“将在后续步骤生效”。
已经关闭：“当前未开启计划模式。
开启：/plan”。

## 5. /permission：知道当前允许做什么

用法：/permission 查询；/permission <真实预设ID> 切换，不支持数字序号。

```text
当前会话权限：{展示名称}
权限 ID：{真实ID}
{能从官方预设可靠读取时展示沙箱与审批策略的中文说明}

可选权限：
{真实ID} — {官方名称或已核实说明}

切换：/permission {一个真实可选ID}
查看任务状态：/status
```

成功：“当前会话权限已设为：{名称}
{实际生效的访问/审批规则，取不到则不补写}

查看权限：/permission”。无需反复加入假想风险警告。
说明边界：修改当前会话的工具执行权限，不授予陌生人私聊准入，也不改变账号的私聊/群聊命令开关。这个区别放在帮助详情，不必每次成功都重复。
无效预设：“没有这个权限预设，当前设置未修改。
发送 /permission 查看可选项。”仅在确认未改动时写未修改。
当前为自定义组合时显示“自定义”，不能用账号默认预设替代，也不能硬编码预设名单。

## 6. /feedback：记录反馈

用法：/feedback <文字>。
无参数：“请在命令后填写反馈。
例如：/feedback 这次回答没有按要求列出来源”。
成功：“反馈已记录到当前会话。
{忠实保留宿主提供的反馈共享状态}

补充反馈：/feedback 补充内容
查看最近对话：/history”。
必须保留宿主关于共享已启用、未配置、禁用或反馈触发共享的披露；不能删除后只剩一句成功。宿主确认记录不等于已经写盘或成功上传，不写“已发送给开发者”“我们会尽快处理”。匿名标识可保留在结果详情，不反复强调。

## 7. /simplify：审查并简化当前项目

用法来自已核对的本地插件：/simplify；/simplify --staged；/simplify --ref <提交引用>；/simplify <文件路径…>。带空格的路径用引号；--staged 与 --ref 不能同时使用。
开始：“正在检查可简化的修改范围。”仅在实际范围收集启动且耗时时发送。
成功受理：“已提交简化审查
范围：{实际文件数量与范围说明}
{存在时展示已跳过项目的说明}

查看状态：/status　补充要求：/steer 保留现有接口”。这是交给 Agent 执行，不能写“简化完成”。
没有可审查改动时保留插件真实返回：不要假定总是没有未提交改动，因为它可能回看上一提交。
参数错误：指出互斥或路径问题，提供实际可用示例；不是 Git 项目时建议 /workspaces 切工作区。未知插件版本若语法不同，以注册描述为准，不继续展示固定示例。

## 8. /export：明确出口

用法：/export；当前 IM 不提供文件回传。
```text
会话日志需要在网页导出，当前不会发送文件到聊天中。

在网页打开这条会话，再发送 /export 下载 ZIP。
查找当前会话：/status
只看最近文字：/history
```

不先回复“已请求下载”再追加限制。无当前会话时先引导创建，不推荐无法执行的历史查询。不要提供仅本机可用、手机却打不开的下载链接。

## 9. 未知动态命令

注册表里存在：保留提供者的名称、参数描述和输出；可以加“已收到 /命令 的返回”标签，不把不确定结果包装成成功。只推荐可确认相关的 /status 或 /history；不能一律推荐 /stop，因为命令可能不涉及运行任务。
注册表里不存在：“没有找到 /xxx。
查看可用命令：/help”。无法可靠计算相似命令时不猜用户想输入什么。
注册表暂不可用：固定内置帮助仍可显示，同时说明“扩展命令暂时无法读取”；不能让一次扩展列表错误使整个 /help 失效（需要调整实现）。

## 10. 所有命令共用的异常与空状态

| 场景 | 推荐回复与后续操作 |
| --- | --- |
| 无当前会话 | 当前还没有会话。直接发送文字，或 /new 开始。 |
| 用户尚未准入 | 按既有准入流程告知待批准；不泄露会话、模型或权限列表。 |
| 命令已关闭 | 此聊天的命令功能未开启，仍可正常聊天。需要使用命令时，请在网页账号设置中开启对应私聊或群聊命令。 |
| 正在合并上一条输入 | 上一条消息正在合并，尚未执行本次命令。等待提交后再发 {原命令名}。不要假装进入批次模式。 |
| 序号过期或无效 | 序号已失效，尚未切换。发送对应列表命令刷新，再用新序号操作。 |
| 参数不支持 | 这个参数暂不支持。正确用法：{当前真实语法}；示例：{有效示例}。需要补参数校验，不能只换文案。 |
| 当前正在运行 | 当前任务仍在运行，暂未切换。/status 查看进度；/stop 请求停止，结束后重试。 |
| 有待回答的问题或审批 | 请先完成刚才的问题或审批，再切换。按实际类型与聊天规则提示，不在群聊推荐批准工具。 |
| 读取列表/状态失败 | 暂时无法读取{对象}，请稍后发送 {对应查询命令}。不能写成“没有数据”。 |
| 会话恢复失败 | 暂时无法打开该会话，原绑定保留。可稍后重试，或在网页查看。仅实际保留时这样表述。 |
| 未实施变更的取消 | 命令已取消，未执行{动作}。只有能可靠确认才说明无改动。 |
| 变更已发生后的取消 | {已完成的动作}；{未完成的后续动作}；{结果ID和恢复方法}。不得统一“命令已取消”。 |
| 不明内部异常 | 未能完成{动作}。{可安全展示的原因}；{重试或网页检查路径}。详情记本机日志，用户回复不贴调用栈、凭据。 |

特别检查：同一错误不能先发“失败”随后又发“成功”；查询附加信息失败不应撤销或否认已经成功的操作。以原始操作结果为准，后续状态查询仅补充。

## 11. 实施顺序和验收

1. 先统一格式与关联命令：/help、/model、/models、/reasoning、各列表、/status、新建和切换。
2. 补可靠状态读取、空状态、分页和参数错误，避免文案宣称超出实现。
3. 为已知扩展增加中文用途和状态对应指引，保留宿主原始结果中有意义的错误和共享披露。
4. 每个命令至少检查查询/成功、空状态或参数错误、操作失败；变更类额外检查部分成功与取消。
5. 钉钉与企微真实手机端验证长消息拆分、换行、复制命令、连续操作，确认无需返回 /help 也能走完模型切换和会话切换。

本方案没有新增命令、没有修改运行代码、没有安装或发布。/menu、/preset、显式批次和 /version 的功能补齐不在本次文案设计内。
