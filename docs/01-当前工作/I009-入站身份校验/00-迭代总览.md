## 目标与业务边界

入站消息在命令、工具审批和注入之前校验发送者。未配置白名单等于谁都不放行。只恢复私聊准入，不恢复钉钉开放模式或群聊白名单。

## 任务清单

- [x] 网关 `handleInbound()` 先做身份校验，默认拒绝
- [x] 恢复设置页待批准 / 批准 / 拒绝
- [x] 接通微信 `allowedUserId`，飞书 / Lark 扫码者入库
- [x] 工具审批仅私聊白名单用户可答
- [x] 补充测试与 SECURITY.md

## 阻塞事项

无。

## 验收标准

- 陌生人的 `/help` 和「批准」都不能驱动助手或放行工具
- 空白名单或缺 `userId` 默认拒绝
- 微信 / 飞书 / Lark / QQ 扫码用户可直接对话；钉钉 / 企微扫码不返回用户身份，仍需批准
- 其他渠道需在设置页批准后才能对话
- 群聊「批准」不会授予 harness 权限
- 现有测试全部通过
