## 目标与边界

两件事：一是修掉 GitHub Issue #13 反馈的「装插件后左侧会话记录不显示」，让插件在 0.1.2、0.1.5 等不含 0.1.7 侧栏接口的宿主上不再把会话列表整块弄没；二是把支持范围推进到 DSH `0.1.7-rc.2`。

边界：不改宿主、不改用户 Profile 数据；不新增设置入口；不改频道列表既有分组、筛选和重命名行为；0.1.7 专属功能（按工作区树分组、归档筛选、双击重命名）在旧宿主上的既有降级维持原样，只保证不再致命。真实手机渠道与真实宿主网页验收仍由维护者负责。

## 问题定位

宿主渲染槽位时对崩溃的注册者是逐条隔离的：只给该槽位画一个空的 crash div（`dsh-client-ui-renderer` 的 `SlotErrorBoundary`）。而插件是用自己的一层（`ImNativeWorkspaceShell`）替换宿主 `sidebar.workspaces` 的官方会话列表组件的，所以插件这层抛出任何错误，用户看到的就是「左侧会话记录不显示」，而不是少个按钮。

具体触发点：`sidebar.workspaces.session.menu.item` 和 `sidebar.workspaces.session.row.action` 都是 0.1.7 才声明的子槽位，宿主 `renderSlot` 对「本 entry 未声明的子槽位」直接抛 `SlotOwnershipError`。真实 `0.1.5-rc.3` 的 `dsh-client-ui-workspace` 只声明 `sidebar.workspaces.directoryFlow`，没有这两个；`0.1.7-rc.1/rc.2` 两个都有。菜单项调用本来有 `hostMenuRendersChildren()` 判断，行内归档按钮的调用没有。

## 已完成

- 新增 `renderHostSlot(renderSlot, key, slotProps, options)`：所有宿主子槽位调用统一走它，宿主没声明该槽位时记一条告警并当作没有内容，不把 `SlotOwnershipError` 抛给宿主。会话行的菜单项和行内归档按钮都已切换过去，菜单项全部落空时退回插件本地菜单项，不再出现空菜单。
- 新增 `ImSidebarFallbackBoundary` 错误边界：包装层渲染失败时用宿主自己传进来的 props 渲染宿主原本的官方组件，等于没装插件时的原生会话列表；没有官方组件可回落时渲染空。原生侧栏外壳和插入别人注册表的频道页签两处都已套上。
- 支持 DSH `0.1.7-rc.2`：peer 并集加入 `0.1.7-rc.2`（保留 `0.1.7-rc.1`，宿主仍可能被桌面端锁定在 rc.1），开发依赖固定到 `0.1.7-rc.2`，CI 矩阵加入 `0.1.7-rc.2`，README 双语支持范围与推荐版本同步。
