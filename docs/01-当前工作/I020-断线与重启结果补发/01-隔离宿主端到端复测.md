# 隔离宿主端到端复测

更新时间：2026-09-11 10:57（Asia/Shanghai）

## 环境与边界

DSH 0.1.5-rc.2，隔离 DSH_HOME，监听 127.0.0.1:10961。插件以 3df688c 为基础，最后对冷会话停止补修替换隔离安装的两份 JS 产物并重启验证。正式 Profile 和正式渠道未改变。

模型端与 Telegram HTTP 端均为本机模拟器；宿主 Agent、持久化、Session Controller、插件入口及浏览器页面为实际运行组件。没有使用真实 Telegram、钉钉或企业微信服务，因此本记录不代表手机或平台回调验收。

## 已通过

| 场景 | 实际观察 |
| --- | --- |
| 未准入消息 | 收到拒绝，模型调用数为 0 |
| 准入后首条消息 | 实际 Agent 运行并经 Telegram adapter 回传正文 |
| 命令 | /help、/models、/history、/rename、/new、/sessions 正常回复 |
| /new 后旧会话 | 频道列表保留旧名，真实网页点击后显示原用户消息与助手正文 |
| 工作区切换 | 经宿主 workspace/create 注册两个测试目录；使用 Windows 反斜杠路径切换成功，新消息回传正常 |
| 发送失败 | 模拟发送 API 持续返回 503，等待实时发送结束后确认 unknown；不在发送中途恢复网络冒充失败 |
| 重启 | 相同 DSH_HOME 重启后全部频道索引和当前绑定保留；sent 与 unknown 没有自动重复投递 |
| 显式补发 | /delivery retry 读取持久化原正文，状态变为 sent；模型调用数前后均为 12 |
| 冷会话停止 | 修复前宿主 cancel 返回 session/not-found；修复后回复当前无运行任务，未增加模型调用；接着发新消息正常恢复 |

## 未通过或未形成有效覆盖的尝试

- 目录仅在磁盘创建、未在宿主注册时切换被拒，这是测试准备不足。通过宿主公开 workspace/create 接口补齐；网页原生目录选择器点击未出现可操作网页弹窗，未将该入口记为通过。
- Windows 正斜杠路径未匹配已注册的反斜杠路径；使用列表原路径可切换。路径等价规范化仍可另行改善，本次不扩展修改。
- 完全空白的模拟模型响应被宿主重试后判为 error，不能作为正常空结果 ended 场景验收；该场景仍只有自动化回归证据。
- 延迟 SSE 结束的模拟响应未观察到 Telegram 增量编辑，实际只在完成时返回正文；流式中断断言没有获得有效覆盖，未记通过。第一次尝试误匹配历史回复，提前触发 /stop，暴露冷会话停止问题；第二次按新模型调用及准确正文等待，仍未触发增量编辑。
- 未完成真实钉钉/企业微信手机排版、卡片点击与断线回调验收，也未覆盖所有渠道的完整外部端到端。

## 后续增量专项复测（0.1.44）

根因已确认：0.1.5-rc.2 AgentLoop 发布 agent/assistant-stream，插件原先只消费旧的 assistant/chunk 持久化事件。接入新版临时增量事件后，在相同隔离宿主中重跑。模拟 SSE 先发第一段，1.2 秒后发第二段，20 秒后才计划结束；收到第二次 Telegram editMessageText 后发 /stop。按原答案 message_id 核对最终内容，仍含两段正文，另有停止提示；断言通过。不能按全局最后一条 edit 判断正文，因为导航卡失效也会产生独立编辑。

流式证据保留在隔离目录 stream-results.json，回归覆盖非文本不外发、未绑定会话不外发及旧事件路径。此结论覆盖本地 Telegram API 模拟器与真实 Host 进程，不扩展到真人手机或其他平台。
