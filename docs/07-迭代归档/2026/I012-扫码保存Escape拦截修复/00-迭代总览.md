# I012 扫码保存 Escape 拦截修复

- 状态：已完成
- 负责人：维护者
- 优先级：P1
- 更新时间：2026-09-02 10:55（Asia/Shanghai）

## 目标与业务边界

修复 I011 遗漏的宿主 Escape 拦截：扫码进入 `saving` 后，Escape 必须保留在弹窗捕获阶段，不能关闭宿主设置页；同时不能取消后台账号保存。只调整浏览器端按键事件顺序及其回归测试，不修改二维码状态机、后端保存或渠道协议。

## 任务清单

- [x] 用失败测试复现 `saving` 时 Escape 继续冒泡
- [x] 先拦截 Escape，再在 `saving` 时跳过关闭逻辑
- [x] 修正绑定弹窗的顺序断言
- [x] 完成聚焦回归与完整回归

## 阻塞事项

无。

## 验收标准

- `saving` 状态按 Escape 不关闭弹窗或宿主设置页
- `saving` 状态按 Escape 不调用二维码取消接口
- 非保存状态按 Escape 仍取消绑定并关闭弹窗
- 全量测试全部通过

## 已完成内容

window capture 阶段的 Escape 监听先执行 `preventDefault`、`stopPropagation` 和 `stopImmediatePropagation`，随后才判断 `saving` 并返回。这样保存中的账号继续落盘，宿主也不会接管 Escape。
