## 目标与边界

修复 [Issue #12](https://github.com/MichengAI/dsh-im-connect/issues/12)：`/new` 只切换当前聊天绑定，旧会话仍可在频道下访问和归档。完成范围为本地代码、构建产物与自动化验证，不含发布或真实 IM 联调。

## 实现与任务验收

- 原有聊天键仍指向当前会话；旧记录以 `history:<sessionId>` 独立保存，兼容旧版平面 JSON。
- 启动通过宿主 `sessionPersistence.list()` 补回可解析 IM ID 的孤立日志索引，保留归档状态，不自动设置为当前会话。
- 历史打开按指定 ID 恢复；恢复失败返回失败，不创建空记录或轮换当前绑定。
- 历史改名、归档与删除按会话 ID 操作，不清除同一聊天的新会话。宿主归档失败不再继续移除列表映射。
- 宿主仅提供活会话列表时不据此清除历史；卸载时持久化服务缺失、查询失败或日志仍存在，均只释放句柄并保留索引。确认日志不存在时清除索引，即使残留归档标记也不阻止清理。
- 新会话用 `pending` 明确标记占位标题，再接受首条原始消息命名。旧记录缺少 `titleSource` 时保留非空名称，不被升级后的普通消息覆盖。
- 同步宿主标题事件与恢复快照，接受 `user`、`provider`、`fallback` 来源，忽略缺失或未知来源。手动标题不被自动结果覆盖；前端保留手动及来源未知的非空标题，其余名称可跟随宿主实时标题。旧名称在收到可靠宿主标题后同步。
- `/help` 对齐 `/new`、`/clear` 的行为，明确旧会话保留在频道列表。
- 控制字符、终端转义、方向控制符清理，兜底标题最多 60 UTF-8 字节，按字素截断。
