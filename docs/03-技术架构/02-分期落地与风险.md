# 分期落地与风险

更新时间：2026-08-16 17:19（Asia/Shanghai）

架构决策见 [总体架构](./01-总体架构.md)。设置页见 [设置页交互](../02-产品与业务/02-设置页交互.md)。

## 1. 落地原则

1. **产品一期**必须交出 5 个可用渠道：微信、企业微信、钉钉、飞书（含 Lark 卡）、Telegram。
2. **工程顺序**仍是先引擎、再安全、再厚协议。不要五条官方协议同一天开工。
3. 设置页第一期就按视觉稿做出来，未接通的渠道显示「配置」，点开可以填，连不上就报错，不要藏入口。
4. 命令只保留离开电脑仍用得上的：`/help` `/status` `/new` `/clear`，以及第二期的批准口令。
5. 实现前先写失败测试：入站路由、命令、审批超时、Secret 不回传。

## 2. 分期

产品一期 = I002 到 I005 全部完成。下面是工程切片。

### I002：插件骨架 + IM助理设置页

范围：

- `package.json`、`cordis.patch.yml`、Host `apply`
- 设置入口名称：**IM助理**
- 设置页按视觉稿还原渠道列表
- 工作区侧栏增加「任务 / 频道」页签骨架（频道先可空）
- 未连接显示「配置」，已连接显示「已连接」+ 开关；第一期开关可先接到空实现
- 状态目录与日志

验收：

- 安装后设置里能看到 **IM助理**
- 工作区能看到「任务 / 频道」两个页签
- 页面层级、卡片、按钮与 [视觉稿](../06-设计资源/01-设置页-IM频道.png) 一致
- 卸载后无残留路由

### I003：引擎闭环

范围：

- `SessionRouter`：每聊天一个会话，挂 `standard` preset（模型跟随当前 profile）
- `followup` 注入，`session/event` 回推最终文本
- `/help` `/status` `/new` `/clear`
- 先用 **Telegram** 打通文字往返（协议最简单，专门用来验引擎）
- Token 进 `ctx.credentials`，回包脱敏
- 已有 Webhook 的 Telegram Token 明确报错

验收：

- Telegram 私聊一句话能打到本机 agent，Web 能看到同一会话
- `/new` 后旧会话不再接收该聊天
- 设置页回包不含 Token

### I004：国内四个渠道接通

范围：

- 微信 iLink：扫码、长轮询、重启免扫码
- 企业微信：扫码或 Bot ID + Secret，长连接
- 钉钉：扫码或 Client ID + Secret，Stream 收消息
- 飞书 / Lark：App ID + Secret，长连接；两张卡共用适配器
- 群聊默认要 @ 或回复机器人才响应
- 有现成能力的渠道可先做「正在输入」，流式编辑能做就做，做不完不挡验收

验收：

- 五个一期渠道都能从设置页连上并完成至少一次文字往返
- 微信扫码一次，重启后自动恢复
- Secret 不进状态接口和日志
- 同一套引擎，渠道之间不复制会话逻辑

### I005：白名单与远程审批

范围：

- 默认拒绝未知用户；设置页待批准
- 平台能返回用户身份时，扫码者自动授权；钉钉 / 企微仍需设置页批准
- 聊天里「批准 / 拒绝」
- 超时回退本机批准
- 多段输入合并

验收：

- 未授权用户不能驱动 agent
- 批准只能作用于当前会话的 pending
- `..` / `!!` 行为符合说明

### 后续（一期之后）

- QQ / Discord
- `im_send_file`、图片入站
- `/workspace` `/sessions` `/continue` `/bind`
- 钉钉 AI Card、企微思考态
- 空闲自动新会话

## 3. I003 / I004 内部顺序

1. 假渠道单测把引擎跑绿
2. Telegram 适配器
3. 飞书（国内协议里文档和 SDK 最完整）
4. 钉钉
5. 企业微信
6. 微信 iLink（扫码与限额最麻烦，放最后）

设置页六张卡从 I002 就在，只是后面几张要到 I004 才能真正连上。

## 4. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 五个渠道并行导致长期不能用 | 一期交不出 | 引擎先用 Telegram 闭环，国内渠道逐个加 |
| 与 dsh-im / dsh-im-gateway 抢同一个机器人 | 消息丢失或互抢 | 允许插件并存，但同一 Bot 禁止两边同时连接；设置页写明 |
| 不挂 preset | agent 没有工具 | 创建/恢复会话强制挂 preset |
| 视觉稿文案带「千问办公」 | 产品名错误 | 只还原布局，文案改「本机助手」 |
| 飞书与 Lark 做成两套代码 | 重复维护 | 一张适配器，两张卡 |
| 微信发送限额 | 长回答发不全 | 分片收敛 |
| 管理 API 暴露到局域网 | Token 被拿走 | 默认只认本机 |
| `allowAllUsers: true` | 群里谁都能驱动本机 | 默认 `false` |
| 审批与本机同时点 | 重复处理 | pending 一次性消费 |

## 5. 回滚

- 卸载：`dsh plugin --profile web remove @michengai/dsh-im-connect`
- 状态目录可整夹删除：`$DSH_HOME\dsh-im-connect`
- 不改 DSH 核心
- 单个渠道可独立断开，不必回滚整个插件

## 6. 已确认 / 默认策略

| 项 | 结论 |
|---|---|
| 一期渠道 | 微信、企业微信、钉钉、飞书（含 Lark）、Telegram |
| 设置入口 | IM助理 |
| 设置页 | 1:1 还原 IM 频道列表稿 |
| 参考项目 | 只读源码学习，本机不必安装那两个插件。 |
| 模型和工具包 | **跟随你当前 dsh 正在用的模型和 preset**。插件不单独再选一套。读不到时才用 `standard`。 |
