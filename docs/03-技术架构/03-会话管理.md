# 会话管理

更新时间：2026-08-16 17:27（Asia/Shanghai）

IM 聊天如何对应 DSH agent，以及为什么不能和网页任务混在一起。界面见 [工作区频道侧栏](../02-产品与业务/03-工作区频道侧栏.md)。

## 1. 已拍板

**对标千问办公：网页任务和 IM 频道是两套会话，必须独立，工作区里分得开。**

| 入口 | 里面是什么 | 出现在哪 |
|---|---|---|
| 任务 | 用户在 DSH 网页里开的会话 | 左侧「任务」 |
| 频道 | 微信 / 企微 / 钉钉 / 飞书 / Telegram 里的聊天 | 左侧「频道」，按渠道分组 |

两边都是本机 DSH agent（有工具、能改代码），但：

- 任务列表里不能出现 IM 会话
- 频道列表里不能出现网页任务
- 一期不做 `/bind`，禁止把某个 IM 聊天钉到当前网页任务上

点「频道」里的一条，只是在工作区查看/继续这条 IM 会话，不会把它挪进「任务」。

## 2. 两个参考项目

### dsh-im

每个渠道自己存 `聊天 → sessionId`，用 HTTP `session.create` 建会话。`/new` 只删映射。  
会话是 DSH 的，但插件当外人去调。Web 任务列表会不会冒出来，取决于 DSH 怎么列会话，插件没有「频道」分区。

### dsh-im-gateway

每个聊天 `ctx.agents.create` 一个 agent，**故意和网页当成同一套会话**，还提供 `/bind` 挂到网页正在跑的会话。  
这正是你不要的：任务和 IM 会混在一起。本项目只借它的「进程内 agent + 事件回推」，不借「和网页混用」。

### 对照

| 点 | dsh-im | dsh-im-gateway | 本项目 |
|---|---|---|---|
| 创建方式 | 各渠道 HTTP | 网关 `ctx.agents` | 引擎 `ctx.agents` |
| 和网页任务 | 可能混进列表 | 就是同一套，还可 `/bind` | **强制分开** |
| 工作区怎么认 | 无专门入口 | 混在会话列表 | **任务 / 频道两个页签** |
| 一个企微会话 | 一条映射 | 一个 agent | 一个 agent，只出现在「频道 → 企业微信」 |
| `/new` | 清映射 | dispose 再 create | 只换这条 IM 会话，不动网页任务 |

## 3. 本项目怎么管

原则：**一个 IM 聊天 = 一个带 IM 标记的 DSH agent。网页任务是另一批，互不登记。**

```
微信张三     →  weixin:dm:张三ID     →  agent（id 前缀 im:）→ 频道 / 微信
企微某群     →  wecom:group:群ID    →  agent（id 前缀 im:）→ 频道 / 企业微信
网页里开的   →  DSH 自己的任务会话   → 只进「任务」
```

### 会话键

```
{channelId}:{kind}:{chatId}
```

Lark 与飞书都用 `feishu`，靠 chatId 区分。`kind` 为 `dm` 或 `group`。

### 创建时必须带的标记

新建 IM agent 时写死这些元数据，供列表过滤：

- 不写 DSH `origin`（该字段只能是 `subagent`）
- `channel`: `weixin` / `wecom` / `dingtalk` / `feishu` / `telegram`
- `chatId`、`kind`
- `title`：有备注/群名就用，没有就先显示平台 ID（截图里那种 `woOoKt...` 是兜底，有名字要换掉）

`sessionId` 使用 `im:` 前缀，例如 `im:wecom:group:woOoKtPAAAAvBcwwV96r5Uw`。

任务列表过滤规则：id 以 `im:` 开头的一律不算任务。  
频道列表只收这些。

若 DSH 核心任务列表无法按 meta 过滤：IM agent 放到独立工作区目录（例如 `$DSH_HOME\dsh-im-connect\workspaces`），避免进当前项目任务。频道列表仍由本插件画。这是退路，不是首选。

### 生命周期

1. 该 IM 键没有会话：创建 id 以 `im:` 开头的 agent，模型和 preset 跟随当前 dsh。
2. 有映射：进程内 get，没有则 resume。
3. resume 失败：新建并改写映射。
4. IM 里 `/new`：只 dispose 这一条 IM 会话。网页任务原样不动。
5. 网页里 `/new` 或新开任务：不影响任何频道会话。
6. 同一 IM 聊天回合未结束又来一句：排队。

注入 IM 用户消息时 `source.kind = 'user'`，这样在「频道」里点开看记录时，气泡仍是用户/助手，不是灰色 context。这只影响这条 IM 会话的呈现，不会把它变成任务。

### 落盘

`$DSH_HOME\dsh-im-connect\sessions.json`：

```json
{
  "wecom:group:woOoKtPAAAAvBcwwV96r5Uw": {
    "sessionId": "im:wecom:group:woOoKtPAAAAvBcwwV96r5Uw",
    "channel": "wecom",
    "kind": "group",
    "title": "",
    "updatedAt": "2026-08-16T09:00:00.000Z"
  }
}
```

正文仍在 DSH session 日志里。平台 token / 游标仍在各渠道文件。

### 一期命令（只作用于当前 IM 聊天）

| 命令 | 行为 |
|---|---|
| 普通文字 | 进这条频道会话，没有就新建 |
| `/help` | 帮助 |
| `/status` | 渠道、会话 id、是否在跑 |
| `/new` `/clear` | 只重置这一条 IM 会话 |

不做 `/bind` `/continue`。设置页只管连接机器人；会话清单在工作区「频道」。

### 重启

读 `sessions.json`，IM 再来消息时 resume。侧栏「频道」按这份映射分组刷新。

### 群聊

群是独立频道会话。未被 @、未回复机器人的群消息，渠道层丢弃。

## 4. 不做什么

- 不把 IM 会话登记进「任务」
- 不把网页任务登记进「频道」
- 不按微信号把多平台合成一个人
- 一期不做 `/bind`
- 渠道代码禁止自己 `agents.create`
