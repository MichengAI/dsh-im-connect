# 总体架构

更新时间：2026-08-16 21:10（Asia/Shanghai）

产品边界见 [产品定位与边界](../02-产品与业务/01-产品定位与边界.md)。分期见 [分期落地与风险](./02-分期落地与风险.md)。会话见 [会话管理](./03-会话管理.md)（与网页任务分列）。

## 1. 选型结论

| 决策 | 选择 | 不选 | 理由 |
|---|---|---|---|
| 形态 | DSH bundle 插件 | 独立守护进程 | 必须复用本机 agent、审批、附件、会话查询 |
| Agent 对接 | `ctx.agents.create` / `followup` | HTTP `session.prompt` | IM 与 Web 共用同一会话；审批和工具才能桥接 |
| 引擎形态 | 中心网关 + 薄渠道 | 每渠道自建 Bridge | 学 cc-connect / gateway，避免 dsh-im 七套会话逻辑 |
| 渠道质量 | 少而可用 | 24 渠道骨架 | 协议深度学 dsh-im，覆盖面克制 |
| 设置通道 | Host HTTP API，仅本机 | 无围栏的局域网 API | 学 gateway 的动态启停，学 dsh-im 的回环默认 |
| 凭据 | `ctx.credentials` + 本地状态 | 明文写进 channels.json | Secret 不回传浏览器 |
| 语言 | TypeScript ESM | 移植 cc-connect 的 Go | 与 DSH / Cordis 同一运行时 |

## 2. 模块划分

```
dsh-im-connect
├── src\                  Host（Cordis 插件）
│   ├── index.ts          apply / Config / inject
│   ├── engine\           会话、命令、审批、合并、分片、回推
│   ├── manager\          渠道启停、白名单、状态落盘、本机 API
│   └── channels\         适配器 + qr\ 扫码绑定
├── plugin-src\client\    设置页（React）
├── cordis.patch.yml      插入 id: im-connect
└── docs\                 交接与架构
```

依赖方向（硬约束，写入 [技术架构基线](../00-交接入口/05-技术架构基线.md)）：

```
client → Host API
manager → engine + channels
channels → engine 类型契约
engine → DSH 服务（agents / session / approval / attachments / tools）
engine 禁止 import 具体渠道实现
channels 禁止创建 agent、禁止解析斜杠命令
```

建议插件声明：

| 项 | 值 |
|---|---|
| 包名 | `dsh-im-connect` |
| Cordis id | `im-connect` |
| 设置页名称 | IM助理 |
| inject | `agents`、`agentPresets`、`sessionQuery`、`userApproval` 或全局 `approval/request`、`tools`、`attachments`、`webServer`、`credentials` |
| 状态目录 | `$DSH_HOME\dsh-im-connect` |

`connection` 是否注入：若设置页走 `webServer` HTTP，则第一期可不依赖 `connection.rpc`。凭据写入仍应走 `ctx.credentials`，API 只收一次性明文并立即转存。

## 3. 运行时数据流

```
IM 渠道
  │  归一化为 ImMessage
  ▼
ChannelAdapter.setMessageHandler
  │
  ▼
Engine.handleInbound
  ├─ 斜杠命令 → 直接回复
  ├─ 批准 / 拒绝 → ApprovalBroker
  ├─ 白名单未过 → 登记待授权
  ├─ 媒体 → attachments / 文本说明
  └─ 文本 → 合并窗口 → SessionRouter
                              │
                              ▼
                     ctx.agents.create / resume
                     agent.followup(user message)
                              │
        session/event ────────┤
        approval/request ─────┤
                              ▼
                     按 sessionId 找回 chat
                     分片 / 编辑消息 / 卡片
                              ▼
                     ChannelAdapter.send
```

入站必须标记 `source.kind = 'user'`，否则 Web 端会把 IM 消息画成 context，看起来像没同步。

## 4. 与 DSH 的对接方式

这是相对 dsh-im 最关键的差异，必须学 gateway，而不是学 dsh-im 的 `HarnessClient`。

| 能力 | DSH 服务 | 用法 |
|---|---|---|
| 建会话 | `ctx.agents.create` | `sessionId` 建议 `im:<channel>:<chatId>:<ts>`，`setup` 必须 `agentPresets.mount` |
| 续会话 | `ctx.agents.resume` / `ctx.agents.get` | `/continue`、进程内 live agent 复用 |
| 注入消息 | `agent.followup` | 用户文本与媒体块 |
| 回推回答 | 全局 `session/event` | `assistant/message`、`assistant/chunk`、`turn/end` |
| 远程批准 | `approval/request` waterfall | IM 答复后返回 `allow` / `reject`；超时交给本机 |
| 发文件回 IM | `ctx.tools` 注册 `im_send_file` | 第二期再做 |
| 图片入站 | `ctx.attachments.saveImage` | 有媒体后再做 |
| 会话列表 | `ctx.sessionQuery` | `/sessions` |

创建会话不挂 preset 时，bash / fs / web 等核心工具会缺失。gateway 已经踩过这个坑，本项目必须一开始就挂 `standard`（可配置）。

创建或恢复 IM 会话时必须带上 `agentOptions.provider/model`：优先用插件配置，否则跟随 Host 的 `agentDefaultModel.currentSelection()`。不能传空字符串，也不能省略，否则 `deployment:persona` 的 `{{model}}` 组装会失败。

不采用 dsh-im 的 HTTP 轮询 `session.history`：

- 会生成 Web 不可见的平行会话
- 无法接入 DSH 本机批准体系
- 流式只能靠插件自己猜事件

## 5. 渠道契约

渠道只实现收发与登录，不实现产品逻辑。

```ts
interface ChannelAdapter {
  readonly id: string
  readonly label: string
  readonly maxMessageLength: number
  start(): void | Promise<void>
  stop(): void | Promise<void>
  send(chatId: string, text: string): Promise<void>
  setMessageHandler(handler: (msg: ImMessage) => void | Promise<void>): void
  status(): string
  loginUrl?(): string | undefined
  sendAction?(chatId: string, action: 'typing'): Promise<void>
  sendMedia?(chatId: string, filePath: string, caption?: string): Promise<void>
  authorizes?(userId: string): boolean | undefined
  openStream?(chatId: string): Promise<EditableStream> // 可选，流式编辑
}
```

能力用可选方法表达，引擎禁止 `if (channel.id === 'feishu')`。这是从 cc-connect 搬过来的原则，必须守住。

入站统一形状：

```ts
interface ImMessage {
  chatId: string
  userId?: string
  username?: string
  text: string
  context?: Record<string, unknown>
  media?: ImMedia[]
}
```

群聊寻址由渠道完成后再交给引擎：未 @、未回复机器人的群消息直接丢弃，不要让引擎猜平台 mention 语法。

## 6. 引擎职责

从 gateway 起步，补 cc-connect 里对 DSH 真正有用的产品能力。

第一期必须有：

- 每聊天一个 agent 会话（`per-chat`）
- `/help` `/status` `/new` `/clear`
- 会话键 `${channelId}:${chatId}` 持久化映射
- 按会话回推最终文本，超长按渠道上限分片
- 渠道忙时同会话串行，避免交错

第二期再加：

- 白名单 + 设置页一键批准
- `批准` / `拒绝` 审批桥
- 手机多段合并（`..` / `!!` / 超时窗口）
- `/bind` `/unbind` `/continue` `/sessions`
- `/workspace` 切换后续会话目录

明确后置（对标 cc-connect，但不进前两期）：

- cron / timer / heartbeat
- `/shell` `/memory` `/model` `/provider`
- TTS / STT
- 多项目编排

## 7. 流式回推策略

| 渠道能力 | 引擎行为 |
|---|---|
| 实现 `openStream` | 听 `assistant/chunk` 与工具事件，编辑同一条消息 |
| 只有 `send` | 回合结束再发完整文本；可选先发「处理中」 |
| 平台卡片（钉钉 / 飞书） | 第三期按可选 `StreamingCard` 能力接入，不进第一期 |

Telegram / Discord / QQ 私聊优先复用 dsh-im 的「发一条再编辑」。gateway 只在回合结束发送，体验明显弱一档，本项目不要停在那一档。

## 8. 配置、状态与界面

配置来源优先级：设置页持久化 > `cordis.patch.yml` > 环境变量。

状态目录 `$DSH_HOME\dsh-im-connect`：

| 文件 | 内容 |
|---|---|
| `channels.json` | 启用状态、凭据引用、白名单、待授权 |
| `sessions.json` | chat → sessionId 映射 |
| `workspaces.json` | chat 工作区偏好 |
| `gateway.log` | 环形运行日志 |

设置页放在「设置 → IM助理」，版面按 [设置页交互](../02-产品与业务/02-设置页交互.md) 还原：

- 渠道卡片：未连接 / 等待扫码 / 已连接
- 扫码渠道直接出二维码
- 凭据渠道展开表单，保存即连接，不必重启
- 待授权用户可一键批准

实现上可参考 gateway 的 `/dsh-im-gateway/api`，路径改为 `/dsh-im-connect/api`。Host 必须把监听限制在本机；若未来要支持局域网管理，单独加 `rpcAuthority: trusted-host`，默认不允许。

浏览器回包禁止出现 token、secret、App Secret、原始用户标识。

## 9. 安全默认值

| 项 | 默认 | 说明 |
|---|---|---|
| `allowAllUsers` | `false` | 与 gateway 开箱放行相反；个人用可在设置里打开 |
| 扫码渠道 | 扫码者自动授权 | 对齐 dsh-im 微信 / 飞书扫码 |
| 手动凭据 | 跟平台应用可见范围，另加待批准名单 | 无法识别扫码人时不能默认全世界可聊 |
| 管理 API | 仅 loopback | 防局域网误暴露 |
| 审批 | pending key 必须匹配当前会话 | 禁止跨聊批准 |
| 群聊 | 默认要被 @ 或回复机器人 | 渠道层过滤 |

微信继续只做 iLink 官方机器人协议，仅私聊、一账号一 poller，文档写明建议专用小号。

## 10. 从三个仓库具体借什么

### 直接借鉴（可参考代码结构，按 DSH 插件重写）

- gateway：`ChannelAdapter`、`ImGateway.handleInbound`、`SessionRouter`、`ApprovalBroker`、`ChannelManager`、设置页动态连接
- dsh-im：微信 iLink、飞书长连接、Telegram 规范化与 Webhook 冲突检测、流式编辑、凭据脱敏、loopback 权限
- cc-connect：能力接口、命令分层、忙时排队、空闲重置、撤回停轮（后置）

### 不搬

- cc-connect 的 Go `engine.go` 和 TOML 项目模型
- dsh-im 的 `HarnessClient` HTTP 轮询
- gateway 的 stub 渠道（Tlon / 元宝 / 语音 / 未完成的 Teams）

## 6. 扫码绑定 API

本机前缀：`/dsh-im-connect/api/channels/:id/qr`

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/start` | 生成二维码并开始后台轮询 |
| GET | `/status` | 查询状态，不含 Secret |
| POST | `/refresh` | 作废当前码并重新生成 |
| POST | `/cancel` | 取消本次扫码 |

成功后 Host 把凭据写入 `ctx.credentials` 或 `secrets.json`，再启动渠道。微信登录态写入 `weixin\wechat-state.json`。钉钉 `accessMode=open` 时该渠道跳过逐人白名单。
