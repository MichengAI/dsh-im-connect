# 主动投递接口

更新时间：2026-09-06 21:21（Asia/Shanghai）

## 实现与兼容

`ChannelManager` 管理账号许可、目标持久化和每账号串行执行；`engine/delivery.ts` 管理校验、分片、取消及结果分类；适配器新增 `sendProactive(route, text, signal)`，不复用回调回复上下文。既有 `send()` 回复契约保持不变。

`channels.json` 的账号记录增加 `deliveryEnabled`（缺省 false）与 `deliveryTargets`（缺省空数组）。目标独立于会话；账号改名不改变 ID；目标路由编辑、发送和账号停用进入同一个队列。已开始的发送允许收敛，停用生效后拒绝后续调用。

新增依赖为 Host 官方 `@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-skill`，要求 `>=0.1.2-rc.1 <0.2.0`。不依赖参考项目。Skill 通过 `ctx.skills.register()` 随插件注册，工具通过 `ctx.tools.register()` 注册，均有卸载清理。

## HTTP

前缀：`/dsh-im-connect/api/delivery`。仅接受回环远端和 Host。写请求必须包含：

```http
Content-Type: application/json
x-dsh-im-connect-client: 1
```

这是本机请求防护，不是公网认证方案。禁止绕过现有 Host/回环校验开放访问。JSON 请求体最多 1 MiB，`text` 最多 256 KiB。

| 方法与路径 | 参数 | 成功响应 |
|---|---|---|
| `GET /accounts` | 无 | `{ ok: true, accounts: [{ accountId, platform, name, connected, limited }] }` |
| `GET /targets?accountId=...` | 账号 ID | `{ ok: true, targets: [...], suggestions: [...] }` |
| `POST /target-save` | `{ accountId, target }` | `{ ok: true, target }` |
| `POST /target-delete` | `{ accountId, targetId }` | `{ ok: true }` |
| `POST /messages` | `{ accountId, targetId, text }` | 投递结果，见下文 |

目标结构：

```json
{
  "id": "tgt_自动生成的UUID",
  "name": "产品研发群",
  "kind": "group",
  "nativeId": "oc_example",
  "idType": "chat_id"
}
```

新建省略 `id`；编辑必须传已有 `id`。`name` 为 1-80 个可显示字符，账号内唯一；每账号最多 100 个目标。`kind` 为 `dm` 或 `group`。`nativeId` 最多 256 字符，无空白、控制字符或 URL 路径。

`idType` 仅飞书/Lark 接受，值为 `chat_id`（缺省）或私聊的 `open_id`。`threadId` 仅 Telegram 群接受正整数。微信只接受 `dm`。未知字段拒绝。保存目标不验证远端可达性，也不隐式发送测试消息。

投递完成后的 HTTP 200 响应示例：

```json
{
  "accountId": "feishu_example",
  "targetId": "tgt_example",
  "status": "sent",
  "sentParts": 1,
  "totalParts": 1,
  "uncertain": false,
  "receipts": [{ "messageId": "om_example" }]
}
```

平台明确拒绝为 `failed`；已有成功分片则为 `partial`；无法确认首片结果为 `unknown`。失败结果带 `error: { code, message }`。不是所有平台都返回消息 ID，回执可以是空对象。不要仅根据 HTTP 200 判断投递成功，应检查 `status`。

发送前校验失败为非 2xx，格式 `{ ok: false, error: { code, message } }`。继承的 HTTP 防护错误使用既有 `{ ok: false, error: string }`。

| 错误码 | HTTP 状态 | 含义 |
|---|---|---|
| `bad-request`、`invalid-text` | 400 | 请求字段或文字不合法 |
| `delivery-disabled` | 403 | 账号未允许主动投递 |
| `unknown-account`、`unknown-target` | 404 | ID 已不存在或账号不匹配 |
| `target-conflict` | 409 | 名称或原生目标重复 |
| `invalid-target`、`invalid-name`、`target-limit`、`unsupported` | 422 | 目标规则或能力不满足 |
| `offline`、`unavailable` | 503 | 账号未连接或插件停止 |

继承接口另有 403（请求防护）、413（请求过大）、415（非 JSON）及 500（内部异常）。平台拒绝、鉴权失败、上下文缺失、取消、未知结果作为投递结果中的错误，不统一变成 HTTP 500。没有幂等键和自动重试；结果未知时调用方先检查接收端。

## Agent 工具

| 工具 | 参数 | 返回 |
|---|---|---|
| `im_accounts` | 无 | `{ accounts }`，仅允许投递的账号 |
| `im_targets` | `accountId` | `{ targets, suggestions }` |
| `im_target_save` | `accountId, name, kind, nativeId`，可选 `id, idType, threadId` | 目标对象 |
| `im_send` | `accountId, targetId, text` | 与 HTTP 相同的投递结果 |

所有工具都校验调用方：无 Agent、`im:` 会话或 `origin=subagent` 拒绝；目标查询和保存只接受允许投递的账号。不能通过修改工具参数切换调用方。拒绝返回 `{ ok: false, error: { code, message } }`；`caller-forbidden` 表示调用来源不允许。

Skill 指导动态发现、名称消歧、参数绑定与失败处理，不包含账号清单或凭据。自动化运行时须能看到上述工具与 Skill，其工具白名单由自动化插件维护，本插件不修改。
